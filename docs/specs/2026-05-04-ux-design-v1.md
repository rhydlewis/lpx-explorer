# 2026-05-04 — UX/UI design spec v1

**Status:** draft, awaiting bead-filing pass
**Inputs:** chat session 2026-05-03/04 (this conversation), `BRIEF.md`, `docs/decisions.md`, `lpx-toolkit/CLAUDE.md`
**Out of scope:** action-on-finding (defer); light/dark theme toggle (defer); PyO3 bindings (defer); Windows/Linux/mobile.

## Summary

lpx-explorer's v1 is a single-window macOS inspector with a left "Library" rail (Tower-style recent + opened-folders list) and a main "Inspector" pane (Logic-Pro-style sectioned read-out of the selected project). Project-first by default — first launch lands on an empty state with two CTAs ("Pick project", "Open folder"); the secondary "browse a folder of projects" JTBD is served by adding folders into the rail without ever leaving the project-centric main view.

## Design principles

1. **JTBD-first, not feature-list-first.** The headline question is *"will this project open cleanly on this Mac, with everything intact?"* Every primary affordance answers that within one glance.
2. **Tower for navigation, Logic for the read-out.** Tower's bookmarks-rail + recent-list mental model maps cleanly onto "Recent + Folders" of `.logicx` projects. Logic Pro's Inspector visual language (small caps section headers, dense info rows, near-black surfaces with a hint of warmth) is the right read-out style for a tool *about* Logic projects.
3. **Single window, no tabs.** Tabs add cognitive overhead with no payoff at this scope. Sectioned scroll inside the Inspector pane handles density; folder breadth is handled by the rail.
4. **Read-only is visible.** A small persistent affordance ("Read-only — never writes to your projects") reassures users that lpx-explorer can't damage their work. This is the wedge over "I'll just open it in Logic to check."
5. **Honour existing investment.** The Python tool's `~/.cache/lpx-toolkit/auval.json` is reused read-only when present. No parallel cache.

### Library rail

- **Always present** when at least one project has been opened or a folder added; hidden on first-launch empty state.
- **Section: Recent.** Most-recent N projects (N = 8 for v1), in-memory only — confirmed *no persistence* for v1.
- **Section: Folders.** Each folder added is a collapsible node. Expanding scans recursively for `.logicx` and lists the projects in alphabetical order. Folder paths are remembered for the session only (no persistence).
- **Row anatomy.** Status dot (12 px) — name (14 px regular) — secondary path/folder hint (11 px, 60 % opacity), truncated middle.
- **Selection.** Single-select. Clicking a row populates the Inspector pane.
- **Search / filter.** Deferred — open question for the bead-filing pass.

### Inspector pane (main)

Vertically scrolling, sticky section header. Five regions in order:

1. **Project header** (always rendered when a project is selected). Bundle name + absolute path. Aria-label: `aria-label="project"`.
2. **Compatibility verdict.** Single coloured pill — Opens cleanly / Has warnings / Will not open. Below the pill, a one-line summary ("3 plug-ins missing on this Mac" / "All plug-ins installed"). Aria-label: `aria-label="compatibility"`. *Requires AU registry lookup; until that epic lands, the verdict reads "AU registry not yet wired" with neutral grey.*
3. **Project info.** Logic's terminology: Key, BPM, time signature, sample rate, modified date. Aria-label: `aria-label="project info"`. *Requires metadata-extraction epic.*
4. **Tracks.** One row per track (Logic terminology), nested rows for Inserts (Logic's term for FX in a channel strip). Audio / instrument / folder / summing-stack distinguished by a small icon + secondary text. Aria-label: `aria-label="tracks"`. *Requires track-registry epic.*
5. **Plug-ins.** Flat inventory of unique fingerprints (the current walking-skeleton output, polished). Status badge per row: installed / missing / phantom. Aria-label: `aria-label="plug-ins"`. *This is the only section that ships fully in the first epic after this spec.*

### Empty state (first launch)

Centred vertical stack:
- App wordmark or simple title.
- Tagline: *"Inspect Logic Pro projects without opening Logic."*
- Two equal-weight buttons: **Pick project** (primary, file dialog filtered to `.logicx`) and **Open folder** (secondary, directory dialog).
- Reassurance line: "Read-only. We never write to your projects."

After first project loads, the empty state never re-appears in the same session — even if the user closes the project, the rail stays.

### Loading & error states

- **Project parse loading.** Inspector shows the project header populated immediately, plus skeleton blocks for Compatibility / Project info / Tracks / Plug-ins. Should resolve in < 100 ms for typical projects; if it doesn't, the skeletons stay.
- **Folder scanning.** Folder node in rail shows a small inline spinner + "Scanning… (12)" with a live-updating count. Cancellable via right-click → Stop scan or by removing the folder. Found projects appear progressively.
- **Project parse error.** Project stays in the rail with a red dot. Inspector pane shows a single error card: human-readable message + collapsible technical detail + "Try again" button. The rest of the layout is suppressed until the user picks another project or retries.
- **Missing AU registry.** Compatibility section renders neutral grey: "AU registry not yet scanned" with a future "Run auval -l" CTA (deferred to AU-lookup epic). Plug-ins section still renders fingerprints but without install-status badges.
- **Project path no longer exists.** Rail row is dimmed; selecting it shows the parse-error state with the message "Project not found at `/path/...`". User can right-click → Remove from rail.
- **Empty folder.** Folder node expands to "No `.logicx` projects found in this folder." (italic, 60 % opacity).

## State management

Three Zustand stores. Confirmed: introduce now, don't wait. Each store + a colocated `*.test.ts`. Pattern mirrors flowcus-v2 (`task-store`, `ui-store`).

### `src/store/library-store.ts`

```ts
interface LibraryState {
  recent: ReadonlyArray<RecentEntry>;       // path + name + last-loaded ms; in-memory only
  folders: ReadonlyArray<FolderEntry>;      // path + scan status + discovered projects
  addRecent: (path: string) => void;
  addFolder: (path: string) => Promise<void>;
  removeFolder: (path: string) => void;
  startScan: (folderPath: string) => Promise<void>;
  cancelScan: (folderPath: string) => void;
}
```

### `src/store/project-store.ts`

```ts
type ProjectStatus =
  | { kind: "idle" }
  | { kind: "loading"; path: string }
  | { kind: "loaded"; path: string; summary: ProjectSummary }
  | { kind: "error"; path: string; message: string };

interface ProjectState {
  current: ProjectStatus;
  select: (path: string) => Promise<void>;   // calls parseProject, updates state
  clear: () => void;
}
```

### `src/store/ui-store.ts`

```ts
interface UIState {
  railVisible: boolean;
  toggleRail: () => void;
  // Future: search query, expanded folder ids, etc.
}
```

State invariants:
- Selecting a project always re-runs `parseProject` (no caching for v1; parse is fast enough).
- A folder scan is independent per folder; cancellations don't touch other folders.
- The currently-selected `project-store.current` and the rail's highlight are derived from the same `path` — never stored twice.

## Acceptance criteria (testable)

- [ ] First launch with no recent / folders shows `<EmptyState>` with two CTAs and the read-only reassurance line. Rail is hidden.
- [ ] Clicking **Pick project** opens the file dialog filtered to `.logicx`. On selection, the project loads and is added to Recent (top of list).
- [ ] After the first project loads, the rail appears. The selected project's row shows a highlight (visual selection).
- [ ] Clicking **Open folder** opens a directory dialog. Once a folder is added, a Folders section appears below Recent. Scanning shows a live count; found projects appear in the folder's expanded list.
- [ ] Each library row renders a status dot (green / amber / red / neutral grey when AU registry not wired).
- [ ] The Inspector pane renders five regions in order: project, compatibility, project info, tracks, plug-ins. Each region has a stable `aria-label` matching the table in §"Inspector pane" (Logic terminology).
- [ ] Switching between projects in the rail updates the Inspector without flicker (skeleton placeholders are visible only during the actual parse).
- [ ] Project parse errors render an error card; the rest of the Inspector is suppressed; the rail row is dimmed with a red dot.
- [ ] Removing a folder from the rail removes it and its children from the library; the currently-selected project (if it came from that folder) clears back to the empty state.
- [ ] Recent list is capped at 8 entries; the oldest entry drops off when a 9th is opened. Duplicates dedupe to the top.
- [ ] All visible text uses Logic Pro terminology — *Tracks*, *Inserts*, *Channel strip*, *Sample rate*, etc. — never developer-facing terms (no *node*, *fingerprint string*, *4CC* in user-visible copy; those are fine in tooltips/dev-tools).
- [ ] App always renders dark — no light-mode CSS is shipped, no `@media (prefers-color-scheme)` block. Light-mode bead is filed separately.
- [ ] No production code uses `any` or type assertions. Tests use real types from `src/lib/types.ts`.
- [ ] `npm run quality` and `cargo test --workspace` are green.

## Edge cases

1. **Folder scan finds zero projects.** Folder node expands to italicised "No `.logicx` projects found." Status dot on the folder is neutral grey.
2. **Folder scan finds 500+ projects.** Progressive rendering — projects appear as they're discovered. The rail uses virtualisation only if scan output exceeds a threshold (decision deferred to bead-filing pass; until then, simple list rendering is fine).
3. **`ProjectData` missing inside a `.logicx`.** Parse returns `ParseError::ProjectDataMissing`. Project keeps a red dot in the rail; Inspector shows the error card.
4. **AU registry cache absent.** `~/.cache/lpx-toolkit/auval.json` does not exist. Compatibility section renders neutral grey "AU registry not yet scanned"; plug-in rows render without install-status badges. Doesn't block any other functionality.
5. **User picks the same project twice.** Recent dedupes — the project moves to the top of the Recent list, no duplicate row appears.
6. **Nested `.logicx` packages.** Logic stores `Alternatives/*/ProjectData` *inside* a `.logicx` bundle, but doesn't store sub-projects. The folder scan must skip recursing *into* `.logicx` directories — treat them as leaves, not as folders to descend.
7. **Very long project names.** Truncate middle in the rail (e.g. "Long pro…name.logicx") with full path on hover. Inspector's project header uses a single-line ellipsis with full path on copy.
8. **Project path no longer exists.** Selecting a row whose path 404s shows the parse-error state with "Project not found." User can remove the row from the rail.
9. **Network volume / slow disk.** Folder scans are async; the UI never blocks. A scan taking > 5 s shows a non-modal "Still scanning…" hint.
10. **Project with zero plug-ins.** Plug-ins section renders "No plug-ins detected." (italic, 60 % opacity). Compatibility verdict reads "Opens cleanly — no plug-ins to check."
11. **Phantom plug-ins (3+ identical fingerprints from undo history).** Render exactly as the parser returns them; do *not* dedupe in this v1. The phantom-filter UX is an open question (see below).

## Open questions for the bead-filing pass

Each one of these is a small `bd decision` candidate. The bead-filing pass should resolve before producing tasks.

1. **AU lookup activation.** When the cache at `~/.cache/lpx-toolkit/auval.json` is missing, do we *invoke `auval -l` ourselves* (slow, can take seconds) or stay neutral grey until the user runs the Python tool? Suggest: in v1, never spawn `auval` — defer to the AU-lookup epic.
2. **Phantom-plugin filter UX.** Three identical `aumf/FXR /SToy` rows appeared in the smoke test. Always-on dedupe / opt-in toggle / always-show-with-grouping?
3. **Library search/filter affordance.** Tower has search-this-list. Useful at hundreds of projects, useless at five. Defer to bead-filing.
4. **Folder scan persistence.** Confirmed *no persistence* for v1 — but we should file the future-persistence work explicitly so it's visible.
5. **Bundle path resolution location.** Per `docs/decisions.md` the parser stays bytes-only; folder scanning lives in the Tauri layer. Confirmed for now. Re-evaluate when a third path-aware feature lands (folder scan + project parse + ?).
6. **Cross-project plug-in lookup.** "Where do I use EZdrummer?" — do we drive this from the rail (filter projects by plug-in) or as a dedicated overlay? Defer; both are workable.
7. **Drag-onto-window support.** Dropping a `.logicx` onto the app window should open it. Easy add; flag for v1.1 unless it's trivial during the AppShell slice.
8. **JSON export.** The Python tool's `--json` is a CLI surface. Native equivalent: File menu → Export project as JSON. Defer.

## Recommended epic decomposition (for the bead-filing pass)

This spec collapses into roughly 6 epics, each of which is implementation-ready with no further design work:

1. **AppShell + EmptyState + dark-mode baseline.** Replace `App.tsx` with the layout grid, ship `tokens.css`, render the empty state. No data flow yet — the existing tracer keeps working through a temporary "Pick project" path that bypasses the rail.
2. **Project store + Inspector skeleton.** Stand up `project-store`, render `<ProjectInspector>` with `<ProjectHeader>` and the renamed `<PluginList>`. The other three Inspector sections are placeholders. Recent isn't wired yet.
3. **Library store + Recent.** Wire the Recent list. "Pick project" now flows: dialog → `project-store.select(path)` → adds to Recent.
4. **Folder scanning.** Add the `scan_folder` Tauri command + `FolderNode` + `AddFolderButton`. Live count, cancellable, progressive rendering.
5. **Compatibility verdict (neutral baseline).** Render the pill in neutral grey ("AU registry not yet scanned") so the IA is in place. The actual AU-lookup logic ships in a separate epic that this depends on.
6. **Polish + a11y.** Aria-labels audit, keyboard navigation across the rail, loading skeletons, error cards, status dots.

Subsequent (out of this spec, dependent on parser epics):
- **Project metadata** populates `<ProjectInfo>`.
- **Track list + FX chains** populate `<TrackList>`.
- **AU lookup** turns the compatibility verdict from neutral grey to coloured + reveals install-status badges in `<PluginList>`.
- **Light mode**, theme toggle, persistence, search, drag-and-drop, JSON export — separate beads each.

## Out-of-scope reaffirmation

To prevent scope creep during bead-filing:
- No write operations of any kind. The existing `tests/readonly_invariant.rs` continues to gate.
- No light/dark theme work — single dark theme. A bead for light mode is filed separately.
- No PyO3 bindings.
