# 2026-05-05 — Aria-label / a11y audit

**Bead:** lpx-explorer-q6o.1
**Spec reference:** docs/specs/2026-05-04-ux-design-v1.md §"Inspector pane" + §"Library rail".

## Spec-mandated regions

Every region the UX spec calls out has the exact aria-label in production code. All use **Logic Pro terminology** — never developer-facing terms.

| Region | aria-label | Component | Element | Verified |
|--------|------------|-----------|---------|----------|
| Library rail | `library` | `AppShell` | `<aside>` | ✓ |
| Project (header) | `project` | `ProjectHeader` | `<section>` | ✓ |
| Compatibility verdict | `compatibility` | `CompatibilityVerdict` | `<section>` | ✓ |
| Project info (metadata) | `project info` | `ProjectInfo` | `<section>` | ✓ |
| Tracks | `tracks` | `TrackList` | `<section>` | ✓ |
| Plug-ins | `plug-ins` | `PluginList` | `<section>` | ✓ |

## Interactive controls

| Control | Pattern | Notes |
|---------|---------|-------|
| `ProjectRow` (rail row) | semantic `<button>` + `aria-current="true"` when selected | text content (name + path) is the accessible name |
| `FolderNode` toggle | `<button>` + `aria-expanded={open}` | text content (folder name + status) is the accessible name |
| `FolderNode` remove | `<button aria-label="Remove folder ${name}">` | the ✕ glyph alone would read as "x" — the explicit label disambiguates |
| `AddFolderButton` | `<button aria-label="Add folder">` with `<span aria-hidden="true">+ </span>` | added in this audit — the leading "+" was getting read literally |
| `LibrarySearch` | `<input type="search" role="searchbox" aria-label="Search library">` | typed text drives `library-store.query` |
| `EmptyState` Pick project | semantic `<button>` | text content ("Pick project") is the accessible name |
| `EmptyState` Open folder | semantic `<button>` | text content ("Open folder") is the accessible name |
| `CompatibilityVerdict` Run AU scan / Try again | semantic `<button>` | text content carries the accessible name |
| `TrackRow` kind glyph | `<span aria-hidden="true">` | decorative emoji — `data-track-kind` carries the semantic info for CSS |
| `StatusDot` | `<span aria-hidden="true">` | decorative — accessible status copy lives elsewhere (verdict pill, scan-status hint) |

## Live regions

| Surface | Pattern | Reason |
|---------|---------|--------|
| Drag-drop hint toast (App) | `<div role="status" aria-live="polite">` | unsupported drops surface a transient hint for the user |
| Inspector parse error | `<div role="alert">` | error replaces the regions; alert is appropriate |
| FolderNode scan failure | `<p role="alert">` (added in this audit) | scan errors fire async — without `role="alert"` screen readers wouldn't announce "Scan failed" |

## Things deliberately *not* labelled

- **Decorative elements**: kind icons in `<TrackRow>` and `<FolderNode>`, status dots in `<StatusDot>`. All `aria-hidden="true"`.
- **Sub-section headings inside the rail** (Recent, Folders): rendered as `<h3>` semantic headings under the rail's `aria-label="library"`. Screen readers pick them up via heading navigation; an explicit aria-label per section would be redundant.
- **`<TopBar>`**: just an `<h1>` with the project name (or app name). No section needed — it IS the heading.

## Logic-terminology vocabulary used

- "library" (the rail) — Logic uses "Library" for its instrument/patch browser; we extend it to mean the project library.
- "project" / "project info" — Logic terminology.
- "compatibility" — neutral, not a Logic word per se but unambiguous.
- "tracks" — Logic's main pane terminology.
- "plug-ins" — Logic's "Plug-ins" hyphenation. Not "plugins" or "plug ins".
- "Inserts" (in `<TrackRow>`) — Logic's word for the FX chain on a channel strip.
- "Channel strip" — referenced in `Track.kind` documentation, not surfaced in the UI yet.

## Excluded from v1

- **Keyboard navigation across the rail** — F.2 (separate slice).
- **Focus management** during state transitions (e.g. moving focus to the error card on parse failure) — defer until F.4 ships error cards properly.
- **`prefers-reduced-motion`** — no animations beyond CSS hover transitions; not relevant.
- **High-contrast theme overrides** — light/dark theme is deferred (`lpx-explorer-sme`); high-contrast follows.

## Net change in this audit

1. `<FolderNode>` scan-error `<p>` gained `role="alert"`. Async scan failures now announce.
2. `<AddFolderButton>` got an explicit `aria-label="Add folder"` and wrapped the `+` glyph in `<span aria-hidden="true">`. Screen readers no longer read "plus add folder".
3. No other spec-mandated label was missing — the discipline of declaring aria-labels at component-creation time has held up across A→F.
